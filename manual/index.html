    User manual¶

    This manual explains how fortvine is organised and how its pieces fit together. The API reference lists every routine and argument; the manual is where the behaviour behind those signatures is described: which defaults are used, what the fitting code actually does, and which options interact.

    Two levels of interface¶

    fortvine ships two Fortran modules:

    module file what it is for
    fortvine_api src/fortvine_api.f90 the typed interface: derived types with type-bound procedures, Fortran-natural array layout u(n, d). This is what Fortran users should use.
    fortvine src/fortvine.f90 the kernels: evaluation, fitting, selection, Rosenblatt transforms, the generic family engine and the bind(C) entry points. Arrays have observations in the last dimension (u(d, n)).

    Everything a Fortran program needs is re-exported by fortvine_api, including the family constants, the fit cache controls and the gen_* helpers of the generic families. The kernel module is only of direct interest if you call the library from another language (see the C interface).

    The three types¶

    fv_bicop
    One bivariate (pair) copula: a family code, a rotation, up to three parameters, the log-likelihood of the last fit and, for the two nonparametric families, an estimate vector aux. Methods evaluate the density, distribution function, both h-functions and their inverses, fit parameters for a given family, or select the family. See Pair copulas.
    fv_vinecop
    A regular vine copula in d dimensions, stored as a structure (an order vector plus a natural-order structure array) and one pair copula per edge. Methods select structure, families and parameters (Dissmann et al. 2013), and evaluate the density, the Rosenblatt transform and its inverse, and simulate. See Vine copulas.
    fv_controls
    A plain record of options shared by every fit and selection: family set, selection criterion, estimation method, tree criterion, truncation, thresholding, threads. Every field has a default, so type(fv_controls) :: ctl is a valid configuration. See Controls.

    A typical session¶

    The usual sequence is: transform the data to the copula scale, select a model, then use it.

    workflow.f90
    program workflow
  use fortvine_api
  implicit none
  integer, parameter :: dp = kind(1.0d0), n = 1500, d = 4
  real(dp) :: z(n, d), x(n, d), u(n, d), sim(5, d)
  type(fv_vinecop) :: vc
  type(fv_controls) :: ctl
  integer :: i

  ! 1. raw data with arbitrary margins (here: a skewed, dependent toy sample)
  call random_seed(put=[(17 * i, i = 1, 33)])
  call random_number(z)
  z = -log(z)                                   ! exponential noise
  x(:, 1) = z(:, 1)
  x(:, 2) = z(:, 1) + z(:, 2)
  x(:, 3) = sqrt(x(:, 2)) + 0.5_dp * z(:, 3)
  x(:, 4) = exp(-z(:, 4)) * x(:, 1)

  ! 2. pseudo-observations: ranks / (n + 1), column by column
  call fv_pseudo_obs_nd(x, u)

  ! 3. structure, families and parameters in one call
  ctl%nthreads = 4
  call vc%select(u, ctl)
  call vc%print()

  ! 4. use the fitted model
  print '(a,f10.2,a,i0)', 'log-likelihood', vc%loglik(u), '   parameters ', vc%npars()
  call vc%simulate(5, sim, seed=1)
  print '(a,4f8.4)', 'first simulated row:', sim(1, :)
end program workflow
    workflow.py
    import numpy as np
import fortvine as fv

n, d = 1500, 4

# 1. raw data with arbitrary margins (here: a skewed, dependent toy sample)
z = -np.log(np.random.default_rng(17).random((n, d)))      # exponential noise
x = np.empty((n, d))
x[:, 0] = z[:, 0]
x[:, 1] = z[:, 0] + z[:, 1]
x[:, 2] = np.sqrt(x[:, 1]) + 0.5 * z[:, 2]
x[:, 3] = np.exp(-z[:, 3]) * x[:, 0]

# 2. pseudo-observations: ranks / (n + 1), column by column
u = fv.to_pseudo_obs(x)

# 3. structure, families and parameters in one call
vc = fv.Vinecop.from_data(u, num_threads=4)
print(vc)

# 4. use the fitted model
print(f"log-likelihood{vc.loglik(u):10.2f}   parameters {vc.npars}")
sim = vc.simulate(5, seed=1)
print("first simulated row:" + "".join(f"{s:8.4f}" for s in sim[0]))
    workflow.R
    library(fortvine)
n <- 1500; d <- 4

# 1. raw data with arbitrary margins (here: a skewed, dependent toy sample)
set.seed(17)
z <- matrix(rexp(n * d), n, d)                             # exponential noise
x <- matrix(0, n, d)
x[, 1] <- z[, 1]
x[, 2] <- z[, 1] + z[, 2]
x[, 3] <- sqrt(x[, 2]) + 0.5 * z[, 3]
x[, 4] <- exp(-z[, 4]) * x[, 1]

# 2. pseudo-observations: ranks / (n + 1), column by column
u <- pseudo_obs(x)

# 3. structure, families and parameters in one call
vc <- vinecop(u, cores = 4)
vc

# 4. use the fitted model
cat(sprintf("log-likelihood%10.2f   parameters %d\n", logLik(vc), vc$npars))
set.seed(1)
sim <- rvinecop(5, vc)
cat("first simulated row:", sprintf("%8.4f", sim[1, ]), "\n", sep = "")

    The raw data are random draws, so the three programs work on different samples and select slightly different vines. The Fortran program is compiled against the built library (see Installation):

    gfortran -O2 -ffree-line-length-none -fopenmp -I build workflow.f90 build/libfortvine.a -o workflow

    Copula scale

    Every routine expects data on the unit square or cube. fortvine does not model margins: use fv_pseudo_obs_nd (ranks) or your own fitted marginal distributions to map the data to \((0,1)\) first. Values are clamped internally to \([10^{-10}, 1-10^{-10}]\), so exact 0 or 1 do not crash, but they carry no information.

    Conventions used throughout¶

    • Array layout (Fortran API). Data matrices are u(n, d): rows are observations, columns are variables. Pair data are two vectors u1(n), u2(n).
    • h-functions. hfunc1(u1, u2) \(= P(U_2 \le u_2 \mid U_1 = u_1) = \partial C/\partial u_1\), hfunc2(u1, u2) \(= P(U_1 \le u_1 \mid U_2 = u_2) = \partial C/\partial u_2\). Details in Pair copulas.
    • Rotations are counter-clockwise rotations of the data by 0, 90, 180 or 270 degrees, following vinecopulib. See Rotations and asymmetry.
    • Family codes are integers: 0 to 25 for the hand-coded families, \(\ge 10000\) for the generic engine. The constants are listed in Family codes and constants and the full list in the catalogue.
    • Variable labels in a vine are 1-based and refer to the columns of u.
    • Threads. Every heavy routine runs on OpenMP threads; the count comes from fv_controls%nthreads, an optional nthreads argument, the FORTVINE_THREADS environment variable or half the logical CPUs, in that order. See Performance.
